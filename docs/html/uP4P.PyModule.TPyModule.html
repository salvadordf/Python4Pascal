Public class function Check(const aPyObject: IPyObject): boolean;

Return true if aPyObject is a module object, or a subtype of a module object. This function always succeeds.

Public class function CheckExact(const aPyObject: IPyObject): boolean;

Return true if aPyObject is a module object, but not a subtype of PyModule_Type. This function always succeeds.

Public class function NewObject(const name_: IPyObject): IPyObject;

Return a new module object with module.__name__ set to name. The module's __name__, __doc__, __package__ and __loader__ attributes are filled in (all but __name__ are set to None). The caller is responsible for setting a __file__ attribute.

Return nil with an exception set on error.

Public class function New(const name_: string): IPyObject;

Similar to TPyModule.NewObject(), but the name is a string instead of a Unicode object.

Public class function GetDict(const module_: IPyObject): IPyObject;

Return the dictionary object that implements module's namespace; this object is the same as the __dict__ attribute of the module object. If module is not a module object (or a subtype of a module object), SystemError is raised and nil is returned.

It is recommended extensions use other PyModule_* and PyObject_* functions rather than directly manipulate a module's __dict__.

The returned reference is borrowed from the module; it is valid until the module is destroyed.

Public class function GetNameObject(const module_: IPyObject): IPyObject;

Return module's __name__ value. If the module does not provide one, or if it is not a string, SystemError is raised and nil is returned.

Public class function GetName(const module_: IPyObject): string; overload;

Similar to TPyModule.GetNameObject() but return the name as a string.

The returned buffer is only valid until the module is renamed or destroyed. Note that Python code may rename a module by setting its __name__ attribute.

Public class function GetName(const module_: PPyObject): AnsiString; overload;

Similar to TPyModule.GetNameObject() but return the name encoded to 'utf-8'.

The returned buffer is only valid until the module is renamed or destroyed. Note that Python code may rename a module by setting its __name__ attribute.

Public class function GetFilenameObject(const module_: IPyObject): IPyObject;

Return the name of the file from which module was loaded using module's __file__ attribute. If this is not defined, or if it is not a string, raise SystemError and return nil; otherwise return a reference to a Unicode object.

Public class function GetDef(const module_: IPyObject): PPyModuleDef;

Return a pointer to the PyModuleDef struct from which the module was created, or nil if the module wasn't created from a definition.

On error, return nil with an exception set. Use TPyErr.Occurred() to tell this case apart from a missing PyModuleDef.

Public class function GetState(const module_: IPyObject): Pointer;

Return the "state" of the module, that is, a pointer to the block of memory allocated at module creation time, or nil. See PyModuleDef.m_size.

Public class function AddObjectRef(const module_: IPyObject; const name_: string; const value: IPyObject): boolean;

Add an object to module as name. This is a convenience function which can be used from the module's initialization function.

On success, return True. On error, raise an exception and return False.

Example usage: 

static int
add_spam(PyObject *module, int value)
{
    PyObject *obj = PyLong_FromLong(value);
    if (obj == NULL) {
        return -1;
    }
    int res = PyModule_AddObjectRef(module, "spam", obj);
    Py_DECREF(obj);
    return res;
 }

To be convenient, the function accepts nil value with an exception set. In this case, return False and just leave the raised exception unchanged.

The example can also be written without checking explicitly if obj is nil: 

static int
add_spam(PyObject *module, int value)
{
    PyObject *obj = PyLong_FromLong(value);
    int res = PyModule_AddObjectRef(module, "spam", obj);
    Py_XDECREF(obj);
    return res;
 }

Note that TPy.XDECREF() should be used instead of TPy.DECREF() in this case, since obj can be nil.

The number of different name strings passed to this function should be kept small, usually by only using statically allocated strings as name. For names that aren't known at compile time, prefer calling TPyUnicode.FromString() and TPyObject.SetAttr() directly. For more details, see TPyUnicode.InternFromString(), which may be used internally to create a key object.

Added in version 3.10.

Public class function Add(const module_: IPyObject; const name_: string; const value: IPyObject): boolean;

Similar to TPyModule.AddObjectRef(), but "steals" a reference to value (even on error). It can be called with a result of function that returns a new reference without bothering to check its result or even saving it to a variable.

Example usage: 

if (PyModule_Add(module, "spam", PyBytes_FromString(value)) < 0) {
    goto error;
}

Added in version 3.13.

Public class function AddObject(const module_: IPyObject; const name_: string; const value: IPyObject): boolean;

Similar to TPyModule.AddObjectRef(), but steals a reference to value on success (if it returns True).

The new TPyModule.Add() or TPyModule.AddObjectRef() functions are recommended, since it is easy to introduce reference leaks by misusing the TPyModule.AddObject() function.

Note: Unlike other functions that steal references, TPyModule.AddObject() only releases the reference to value on success.

This means that its return value must be checked, and calling code must TPy.XDECREF() value manually on error.

Example usage: 

PyObject *obj = PyBytes_FromString(value);
if (PyModule_AddObject(module, "spam", obj) < 0) {
    // If 'obj' is not NULL and PyModule_AddObject() failed,
    // 'obj' strong reference must be deleted with Py_XDECREF().
    // If 'obj' is NULL, Py_XDECREF() does nothing.
    Py_XDECREF(obj);
    goto error;
}
// PyModule_AddObject() stole a reference to obj:
// Py_XDECREF(obj) is not needed here.

Soft deprecated since version 3.13.

Public class function AddFunctions(const module_: IPyObject; functions: PPyMethodDef): boolean;

Add the functions from the nil terminated functions array to module. Refer to the PyMethodDef documentation for details on individual entries (due to the lack of a shared module namespace, module level "functions" implemented in C typically receive the module as their first parameter, making them similar to instance methods on Python classes).

This function is called automatically when creating a module from PyModuleDef (such as when using Multi-phase initialization, TPyModule.Create, or TPyModule.FromDefAndSpec). Some module authors may prefer defining functions in multiple PyMethodDef arrays; in that case they should call this function directly.

The functions array must be statically allocated (or otherwise guaranteed to outlive the module object).

Public class function FromSlotsAndSpec(const slots: PPySlot; const spec: IPyObject): IPyObject;

Create a new module object, given an array of slots and the ModuleSpec spec.

The slots argument must point to an array of PySlot structures, terminated by an entry with slot ID of 0 (typically written as PySlot_END). The array must include a Py_mod_abi entry.

The spec argument may be any ModuleSpec-like object, as described in Py_mod_create documentation. Currently, the spec must have a name attribute.

On success, return the new module. On error, return nil with an exception set.

Note that this does not process the module's execution slot (Py_mod_exec). Both TPyModule.FromSlotsAndSpec() and TPyModule.Exec() must be called to fully initialize a module. (See also Multi-phase initialization.)

Public class function GetState_DuringGC(const module_: IPyObject): Pointer;

The following function should only be used in a tp_traverse handler; calling them in other contexts may have unintended consequences.

This function act like their counterpart without the _DuringGC suffix, but it's guaranteed to not have side effects, it doesn't set an exception on failure, and it returns/sets borrowed references as detailed in the individual documentation.

Note that this function may fail, but as it doesn't set an exception, no error information is available. In some cases, failure is not distinguishable from a successful nil result.
